# Friction log

Record anything that cost more than ten minutes, and the pipeline fix that removes it. The goal is
that the next agent does not hit the same wall.

| Date | Workstream | Friction | Pipeline fix |
|---|---|---|---|
| 2026-10-27 | setup | Contract tests failed on Node 22.22 because `.ts` files were passed straight to `node --test`. | `@splice/contracts` now runs tests with `node --import tsx --test`, like the backend. |
| 2026-10-27 | setup | The root filesystem has ~350 MB free; `npm ci` filled it. | `node_modules` is a bind mount on the 100 GB scratch disk; use `npm ci --cache /mnt/nvme1n1/npm-cache`. |
| 2026-10-27 | builders | Bubblewrap could not create namespaces with a low process limit, and Node's V8 virtual address reservation exceeded a small address-space limit. | `runRestricted` now uses a process limit above the host UID count and a 4 GiB virtual address limit; builders run their public tests inside bubblewrap. |
| 2026-10-27 | runtime | Early worker tests passed in source but the exported host could not find its worker entry, and inherited `--input-type` flags broke startup. | The current runtime build copies the isolated JS runner to `dist`; the desktop smoke launches the exported app and checks a restart. |
| 2026-10-27 | native | The generated C shim wrote an `int32_t` through pointers to narrower integer fields. | Native v1 now rejects integer types other than signed 32-bit and signed 64-bit, with a test; a later shim can add width-specific parsing. |
| 2026-10-27 | verification | The root test command stopped at backend tests because Node 22.22 could not load `.ts` files directly. | The backend `test` script now uses `node --import tsx --test`, preserving the existing test glob and assertions. |
| 2026-10-27 | native export | A native build could compile helper C files yet store only its entry C file, making the source export incomplete. | The builder compiles all declared C translation units and records every declared C/header file in the package artifacts; a two-file sidecar test verifies this. |
| 2026-10-27 | runtime isolation | Node worker threads could import host filesystem modules, despite the built package's static source checks. | Both JS and native packages now launch as supervised Linux processes in bubblewrap namespaces with read-only package mounts and no network; tests probe host file and TCP access, and the Electron export ships the JS protocol runner. |
| 2026-10-27 | runtime isolation | Explicit package environment values would have reached the outer launcher, allowing loader variables to affect `prlimit` or bubblewrap before namespace setup. | The outer launcher now receives only a fixed PATH; validated package variables are set by bubblewrap inside the namespace. |

| 2026-10-27 | generality | A supposed second recipe only changed the notebook title and a package pin, so it did not test a different plan shape.
